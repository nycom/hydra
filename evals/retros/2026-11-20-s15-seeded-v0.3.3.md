- No seed was discarded. The author's only commits touched `ledger/report.py` and `tests/test_report.py` (c031e75), and the merge's shared commit touched README (a478bfb). No seeded line was touched.
- False minor in a workstream: `v1-F1` (stage validate, minor, kind docs). It said "the brief's shared edit is missing" in `alpha-report`, and the validator itself wrote "If the coordinator applies shared edits at merge time this is expected". `sharedEdits` already carried the README intent, and the merge applied it (commit "Update shared files for alpha-report").

- Duplicate whole-branch findings: the reviewer (W-F1..F7) and the validator (V-F1..F9) both independently filed 7 of the 8 seeds. The validator alone filed a separate D8 finding (V-F8); the reviewer mentions the deletion only inside W-F5. So the fix and recheck prompts carried 17 non-scope entries for 8 seeds. The recheck was the second most expensive agent by output (6,232; 41k total tokens).
- V-F10 (drop the out-of-scope tidy commit) was answered as "fixed forward" (`repos[alpha].notes[0]`). It is scope-only.
- Ordering, not a late catch: the reviewer and the validator caught D6 (W-F1, V-F1), and fix r1 repaired it before the contract agent ran. `crossRepo.sections` reports the contract "byte-identical… sends total_cents", so the contract agent was never tested on D6.

   `const MERGE_EDITS = edits => \`Shared-file edits are applied by the merge on the feature-branch tip, never in this range: a brief criterion on a shared file is met when the author's sharedEdits carry it (${edits.length ? JSON.stringify(edits) : 'none returned'}). Its absence from this range or head is never a finding; only a brief shared edit missing from that list is (minor).\``
   Then use it twice. Line 415: `…against the code and a command you ran. ${MERGE_EDITS(out.sharedEdits)} ${REFUTE}`. Line 467: append `${MERGE_EDITS(out.sharedEdits)}` after `${EVIDENCE}`.
