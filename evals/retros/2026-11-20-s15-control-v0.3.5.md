## Changes, ranked
1. target: hydra
   what: treat a validator result that never ran its gate as a dead attempt in `step()` (workflow.js ~line 297), retried up to 2 times and then "died 3 times" → NOT merged.
   - Schema: `GATE_OUT` (~line 156) gets a required `command: { type: 'string', description: 'the exact gate command(s) you executed at this head in this step; empty if you ran none' }`.
   - Call sites: pass `gated: true` at every call site whose prompt carries a gate. These are the workstream validates (~432, ~484), wb validate (~620), recheck (~680), and docs validate with `gated: !!gate` (~763; its "no gate" branch stays exempt).
   - In step():
     `const unrun = opts.gated && r?.gate && (!r.gate.command?.trim() || /^\W*(skip(ped)?|not run|n\/?a)\W*$/i.test(r.gate.summary))`
     Then `return` only when `r && !malformed && !unrun`. Do not keep an unrun result as `bad` (that slot is for sha repair). The retry tail: "the previous attempt returned without running the gate; redo the whole step and run every command".
   - Add a tests/ scenario where the mock validator first returns `summary: "skipped"`. It should expect a second validate agent, and no merge if all 3 skip.
   - Weighed alternatives:
     - The summary regex alone (XS) catches exactly this case but not a bare "tests pass".
     - The `command` field turns a lazy skip into an explicit lie, and the script can also check that `command` contains the workstream's `gate` text.
     - An exit code can't gate green, because the known-red failure makes exit 1 normal, so it was left out.
     - The script cannot see tool calls.
   evidence: `beta-report validate c1` result `gate.summary = "skipped"`, `verified []`, `open []`, followed by `beta-report merge`.
   expected gain: no workstream merges on an unvalidated head. Cost is one retry in about 4% of validator calls.
   cost: S
2. target: hydra
   what: in `promote()`, return the agent's notes as a warning even when `ok` is true, if they report a step not done. The caller adds them to `repos[].notes`.
   evidence: both docs promote notes say "Step 3 NOT done", and `feat/eval--docs` is still on the remotes.
   expected gain: no silent leftover side branches; the user sees the cleanup step to run.
   cost: XS
3. target: hydra
   what: give the clean-review DELTA a short `evidence` string (commands run per step), the way VERDICT has `tests`.
   evidence: the skipped validator also skipped acceptance, the red-proof and the trial merge, and the schema had no field that could show it.
   expected gain: a skipped step becomes visible in the result and to a future script check.
   cost: S
