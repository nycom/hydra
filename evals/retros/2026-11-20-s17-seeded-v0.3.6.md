## Changes, ranked
1. target: hydra
   what: the first validator of a workstream runs the test guard over the whole workstream range (`origin/<feature>...head`), whatever the cycle, the same way `accept()` runs once. Later delta validators keep judging only the delta.
   evidence: `evidence["validate c1 delta"]` saw the weakened owners assertion and did not file it. W3 reached the merge and was caught only as `V-F2` (wb-validate).
   expected gain: a weakened pre-existing test is caught before the merge, and the whole-branch fix round it cost goes away (about 5K output, 2 agents). Pair it with an S17 scoring line that counts that validator's test-guard findings as `test-guard`.
   cost: S
2. target: hydra
   what: two prompt rules for a brief conflict.
   - Fixers: when a finding can only be fixed by breaking another clause of the brief, do not pick a side. Answer `question` with both options, and default to the option that keeps behaviour and tests.
   - Whole-branch validator: a finding that reverses a workstream finding's verified fix goes to `repos[].questions`, not to the fix loop.
   evidence: fix c1 notes "that needs a decision" but returned `questions: []`. `V-F1` reversed the verified `c1-F1` fix. fix r1 deleted two guard tests, `D-F1` is open, and the oracle shows W1, W2 and W4 at the shipped 8234408.
   expected gain: the user settles the conflict once. This avoids one fix round, a failed docs pass and shipping a reverted fix.
   cost: S

   evidence: recheck r1 accepted "two test functions … removed, which V-F1 justifies". `D-F1` (docs) caught it later.
   expected gain: the regression is caught at recheck, not docs, and the docs commit is not stranded.
